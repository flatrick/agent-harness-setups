# Rubber-duck: Agnostic Persistence Migration

### Idea (as floated)
Move the `rubberduck` persistence path from `.claude/rubberduck/` to `.agents/rubberduck/` to make the harness provider-agnostic.

### Holes, gaps & failure modes
**Namespace Collision**: `.agents/` is a shared root. Without a strict enforcement of unique subdirectories per agent, different agents (or different instances of the same agent) could collide. You are trading a "provider-specific" mess for a "shared-space" mess. If the slugging logic isn't coupled with a "claim" or "reservation" system, it's brittle.

### Improvements / stronger alternatives
Enforce a strict `agent_id` namespace. Instead of just `.agents/rubberduck/`, the harness should ensure the path is always `.agents/<agent_id>/<topic_slug>/...`. This ensures that even in a shared directory, the "duck" owns its space and cannot be overwritten by a "scout" or a "designer".

### Open questions
Does the current harness provide a way to "claim" a folder in `.agents/`, or does it just blindly write?

### Where it stands
The idea is valid for portability but requires stricter namespace isolation to be production-grade.
